项目概述

大学生社团管理平台是我独立完成的毕业设计。它围绕高校社团的日常业务，把社团信息、入社申请、活动报名，以及参与后的签到、游记和评价放到同一个 Web 平台中。

为什么做这个项目

社团信息、成员资料和活动记录分散时，申请进度与后续参与情况不容易衔接。这个项目希望把这些环节连接起来，让普通用户能够查询与提交申请，让社团负责人和管理员能够处理对应的业务记录。

我的角色

我独立完成这份毕业设计，内容覆盖需求分析、数据库设计、用户端与管理端页面、后端接口和联调。留存成果包括前后端源码、数据库脚本、设计论文和演示视频。

三类角色如何协作

  • 普通用户：浏览社团与活动，提交入社申请和活动报名，在个人中心查看入社、退社、报名、签到等记录，并参与游记、评价与留言。
  • 社团用户：维护社团与活动信息，处理申请及参与记录，查看活动相关数据。
  • 系统管理员：管理用户、处理审核、维护公告和留言，并查询各类业务记录。

从注册到审核再到登录

演示视频保留了一条完整的社团用户处理流程：

  1. 在用户端选择社团用户身份并提交注册信息。
  2. 新账号在管理端显示为「未审核」。
  3. 管理员处理后，账号状态更新为「已通过」。
  4. 账号通过审核后，回到用户端完成登录。

后端登录处理会查询对应用户的审核状态，对未通过审核的账号返回提示。这条流程把注册表单、管理端处理、后端状态和登录反馈衔接起来。

活动报名与后续记录

报名接口包含活动人数上限和截止时间检查，保存报名记录后更新活动名额。报名、取消、签到、游记与评价分别保留对应的业务记录，便于用户和管理人员查询不同阶段的信息。

技术实现

用户端与管理端分别维护为两个 Vue 3 前端工程，使用 Vite 构建。Spring Boot 后端提供业务接口，MyBatis-Plus 配合 MySQL 处理数据读写，Redis 保存登录令牌。

页面、控制层、服务层和数据访问层围绕用户、社团、活动及各类记录组织，方便逐个梳理业务之间的关系。
