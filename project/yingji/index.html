项目概述

「影迹」是一款面向个人使用的 Android 影视记录与智能观影应用，把影视兴趣、应用开发与 AI 产品探索结合起来。

项目由我个人开发完成。观影记录、观影习惯记录和基于观影习惯的影视作品推荐均已可用，目前仍在持续完善体验。

项目已开源：查看 GitHub 源码与文档 ↗ · 查看版本发布与 APK ↗

为什么做影迹

我了解到，一些用户在观看影视作品时，不便记录自己的观影记录与观影习惯，也希望能根据自己的习惯获得影视推荐。「影迹」围绕这些需求展开，让记录与推荐在同一款应用中衔接起来。

我的角色

个人开发完成。

目前可用的核心功能

  • 观影记录：记录观看过的影视作品。
  • 观影习惯：记录个人观影习惯。
  • 影视推荐：根据观影习惯推荐影视作品。

基础记录能力

  • 作品管理：管理个人影视记录。
  • 分类与标签：通过分类和标签整理作品。
  • 观看状态：记录作品的观看状态。

AI 观影推荐

基于观影习惯的影视作品推荐已可用。项目已接入 DeepSeek API，并继续围绕个人观影记录与偏好探索观影画像。

推荐如何形成

  1. 准备候选：通过资料网关读取 TMDB 电影、剧集候选，并核对对应详情。
  2. 确认偏好摘要：在个性化推荐前，向用户展示本次使用的画像摘要，确认后再发起模型请求。
  3. 理解推荐方向：DeepSeek 根据偏好摘要提供主题方向与筛选条件。
  4. 筛选与排序：应用依据候选资料、偏好和条件在本地完成筛选与排序。

作品名称和详情来自影视资料源，模型输出限定为推荐方向与条件。

产品定位

当前以个人使用为主，优先本地使用与成本控制，不以多用户商业化为第一目标。

开发中遇到的难点

难点在于让推荐对应到可核对的真实影视资料，并处理资料获取链路中的网络与异常问题。

目前，作品资料使用 TMDB 数据源，应用通过独立的资料网关读取候选、详情与海报，再核对作品信息。DeepSeek 提供偏好方向与筛选条件，应用据此对候选进行筛选和排序。

这一实现将影视资料、模型建议和本地排序分开处理。缺少有效候选时保留空结果，资料请求失败时提供错误反馈。资料源接入仍在持续完善与验证。

开发记录中曾出现上游直连受限，并记录过经代理完成本机只读验证的过程。资料网关的持续接入与验证，是这一部分后续完善的重点。

当前进展

在已有基础记录与 AI 功能之上，继续完善交互、测试和功能体验。公开发布页已提供 v3.0.0，后续版本、安装包与更新说明以 GitHub Releases 为准。下方界面与视频来自独立验收版，不作为公开安装包的实测记录。

真实调用与测试模式

真实模型调用需要启用对应构建配置、配置模型凭据，并确认本次画像摘要；开发版本同时保留 Mock 测试模式。真实调用效果示例仍待补充。
